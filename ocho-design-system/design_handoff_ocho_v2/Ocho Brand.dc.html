Why red survives the traffic-light objection
Red does mean stop on a road, and work is when you go — but in every timer, heart-rate zone and effort scale your users have already met, red means hard. Category convention beats the road here, and the instruction is carried by the beep and the label, not the hue.
Why rest moves to green-200
The states then differ by lightness, not just hue, so they stay distinct with no colour vision at all. Text polarity flips with them — white on work, ink on rest — which is a second, redundant signal. Rest should read quieter than work anyway.

The error problem this direction creates
Errors leave the phase layer entirely
All four signal colours are spent on phases, so red can no longer mean "wrong". The fix is structural, not chromatic: phase colour is only ever a full-bleed background; errors are only ever a tinted plate inside the layout. Same hue, different surface, no ambiguity.
Timer drifted while backgrounded
Battery optimisation is on for Ocho. Exempt the app to keep the clock exact.
Never both at once
A red error plate must not appear over a red work screen. Errors raised mid-session wait for the rest interval, or surface in the notification instead — the running clock is never covered.

enum class Phase { PREPARE, WORK, REST, COMPLETE }
data class PhaseTheme(val plate: Color, val onPlate: Color)
// Full-bleed plate behind the clock
fun phaseTheme(p: Phase, dark: Boolean) = when (p) {
Phase.PREPARE -> if (dark) PhaseTheme(Color(0xFFA8720A), N0)
else PhaseTheme(Color(0xFFE8A317), N950)
Phase.WORK -> if (dark) PhaseTheme(Color(0xFFB3282D), N0)
else PhaseTheme(Color(0xFFE5484D), N0)
Phase.REST -> if (dark) PhaseTheme(Color(0xFF5CA47C), N950)
else PhaseTheme(Color(0xFFB0D8BE), N950)
Phase.COMPLETE -> if (dark) PhaseTheme(Color(0xFF5645C4), N0)
else PhaseTheme(Color(0xFF7C6CF0), N0)
}
// Errors never use the plate — tinted surface, inside the layout
val ErrorSurface = Color(0xFFFDE0E1) // --red-100
val OnErrorSurface = Color(0xFFB3282D) // --red-700

Behaviour
Rules that only matter because this runs on a phone, mid-workout, at arm's length.
Phase transition
The full-screen colour swap runs 340ms on --ease-in-out. The beep and haptic fire on the frame the interval flips — never delayed by the animation.
Reduced motion
Animator duration scale of 0 zeroes the crossfade. The colour still swaps instantly — motion is decoration here, colour is information.
Touch targets
48dp minimum, everywhere. The session screen's start/pause target is 96dp — it gets hit with sweaty hands and no attention.
Screen stays on
A running session holds the screen awake and keeps the notification live, so the clock survives a lock and a backgrounding.
Button states
Hover darkens one step, press darkens two and shifts 1px down. No scale transforms.
Voice — empty states and errors
Presets appear here after you save a workout.
